# USART10 采集 IMU 安装方向

## 当前临时使用 USB 文本

USART10 暂未收通，当前配置 `GIMBAL_USB_IMU_TEXT_DEFAULT=1`，先通过开发板
USB 虚拟串口打印相同的 IMU CSV。原 USART10 输出仍独立保留。

1. 使用“编译并烧录”更新固件。
2. 关闭占用开发板 USB COM 口的 VOFA+。串口助手选择开发板的
   STM32 Virtual COM Port，115200 / 8N1 / 无流控，文本显示、关闭 HEX、关闭自动发送。
   这里使用开发板 USB 的端口，CH340 的 COM 口暂不用。
3. 遥控器 OFF、摇杆居中，上电静止等待 IMU 初始化。看到 `# USB_IMU v2`、
   `#type,...` 和连续的 `IMU,...` 后，先发送 `stop` 确认 stage=0，再按下方动作顺序采集。
4. USB 文本和原 JustFloat 波形互斥，同一 COM 口不能由两个软件同时打开。

在 USB 口发送 ASCII 命令并添加换行（发送框填命令，行尾选 `\n`）：

| 命令 | 效果 |
| --- | --- |
| `imu 0` | 恢复原 48 通道 JustFloat 波形，并开始发送；关闭串口助手后用 VOFA+ 打开同一 COM |
| `imu 1` | 切回 20 Hz 左右的 IMU 文本，并开始发送 |
| `stop` | 保留原功能，切到 stage=0，两轴零输出 |
| `stream 0` / `stream 1` | 暂停 / 恢复当前格式的数据流；命令应答仍会发出 |

文本应答示例：`# ACK seq=1 result=1 value=0.000 stage=0 stream=1`。
`result=1` 成功，2 为语法错误，3 为数值超范围，其余沿用原 VOFA+ 返回码。
文本模式下 `rate` 仅保存 VOFA+ 波形频率，文本固定为 50 ms 时隙。
`imu 0/1` 不改变 PID、机械限位或电机控制阶段；USB 模式切换仅在 RAM 生效。
重启仍按上述默认值选择文本。之后彻底改回时，把集中配置的
`GIMBAL_USB_IMU_TEXT_DEFAULT` 设为 0 后重新编译烧录即可。

## 原 USART10 输出

保留现有 USB 虚拟串口、VOFA+ 48 通道 JustFloat 和在线命令；另外从 USART10
输出 CSV 文本。sentry、infantry 均启用。无需发送开始命令，IMU 初始化和上电校准
完成、任务启动后自动打印，约 20 Hz；每秒一个发送时隙用来重发列名，便于晚连接。

## 接线和串口助手

使用 **3.3 V TTL 电平的 USB 转串口**，板子保持原有供电：

| 开发板信号 | USB 转串口 |
| --- | --- |
| USART10_TX / PE3 | RXD |
| GND | GND |
| USART10_RX / PE2 | 本次只打印，可不接 |

不需要接 USB 转串口的 VCC。电脑选转接器自己的 COM 口，开发板 USB 的 COM 口
继续给 VOFA+ 使用。设置 **115200 / 8 位数据 / 无校验 / 1 位停止 / 无流控**，
关闭 HEX 显示，按文本保存接收数据。这里无需发送 `stop`，命令仍在原来的 USB 口接收。

**说明书存在编号冲突：**《DM-MC-Board02 使用说明书 V1.1》印刷第 7 页的三行
UART10 表写 1=GND、2=TX、3=RX，但同页 P15 四针原理图画的是
1=5V、2=GND、3=RX(PE2)、4=TX(PE3)。不要直接照三行表数四针插座。
按实际板子的接口丝印/线序核对 TX、GND；若接口对应该页 P15 四针图，使用
**P15-4 TX 和 P15-2 GND**。无清晰标识时先核实线序，不把 5V 当作 TX。

## 第一次采集

1. 固定好板子，让板子和俯仰支架一起运动；采集过程中不能松动。整机底座固定。
2. 编译、烧录；遥控器放 OFF、摇杆居中。当前配置上电 `stage=1`，先通过 USB 发送 `stop` 切到0再手动采集。
   可在原 USB VOFA+ 上发 `stop\n`，确认 stage=0、两轴输出=0，再用手移动机构。
3. 枪头靠下限位静止，**等 IMU 上电校准完成**。打开转接器 COM 口，看到表头及
   `IMU,...` 行后，确认 `valid=1`、`cal=1`、`imu_seq` 持续增长、`imu_age_ms` 较小。
4. 开始保存接收数据，先静止 **5 秒**。
5. 保持 Yaw 不动，用手缓慢向上抬 Pitch **3 秒**，停住 **2 秒**，缓慢向下放
   **3 秒**，停住 **2 秒**。只沿俯仰轴运动，不必抬到竖直，也不必准确水平。
6. 用手保持同一个俯仰姿态，向右转 Yaw **3 秒**，停住 **2 秒**，再向左转
   **3 秒**，最后静止 **5 秒**。旋转时不要同时改变 Pitch，放下时用手托住。
7. 停止保存，把完整 `.txt` 日志提供给分析者，并注明动作顺序、有无同时运动或松动。

这里先辨认传感器轴与真实俯仰/偏航轴、正负方向。一次动作日志不能直接保证最终
安装变换准确；静止重力方向和两个独立转轴数据需要一起分析，再回到波形验证。
传感器坐标系的 gx/gy/gz 不会随着软件安装角设置改变，方便辨认任意固定安装方向。

## 文本列说明

每行以 `IMU` 开头，逗号分隔，以 CRLF 结束；`#` 行是说明/列名。
打印到小数点后三位，不使用浮点 printf。非有限或超范围数值打印 `nan`。

| 列 | 含义 |
| --- | --- |
| t_ms、imu_seq | 控制快照时间和 IMU 样本序号；不是每行都必须序号加 1 |
| valid、cal、imu_age_ms | 是否已有姿态、在线校准是否成功、样本距控制快照的时间 |
| yaw_deg、pitch_deg、roll_deg | INS 当前解算姿态，单位度，已应用配置的安装变换；此仓库 Pitch 对应 X 旋转、Roll 对应 Y 旋转 |
| gx_dps、gy_dps、gz_dps | **安装变换之前的传感器轴**角速度，已扣除陀螺零偏，单位度/秒 |
| ax_ms2、ay_ms2、az_ms2 | **安装变换之前的传感器轴**加速度，含重力，单位 m/s²；静止合模约 9.8 |
| yaw_ecd、pitch_ecd | 两电机原始编码器值，范围 0～8191 |
| yaw_age_ms、pitch_age_ms | 电机反馈距控制快照的时间；大于 30 ms 时不能把编码器当作新数据 |
| stage、state、fault | 当前控制阶段、状态、故障位；不是安装校准结果 |
| yaw_out、pitch_out | 驱动记录的两轴 CAN 输出命令，手动采集前确认均为 0 |
| tx_skip | 串口忙/发送失败/格式失败累计跳过次数，正常应不持续增长 |
| rc_online、sw_left、sw_right | 遥控在线；左右拨杆原始值，下/中/上=2/3/1 |
| stick_yaw、stick_pitch、centered | 右摇杆水平/竖直原始值，centered=1 表示落在 ±80 的当前死区内 |
| request、axis_mask | 请求 OFF/HOLD/MANUAL=0/1/2；仅 Yaw/仅 Pitch/双轴=1/2/3 |

姿态存在不适合当前云台控制的安装方向时，控制可能报 IMU 故障，但日志仍保留
新鲜的传感器向量，便于排查。`valid=1` 只表示已发布过姿态，必须结合 cal、序号
和 age 判断健康。串口断线不会阻塞控制，也不依赖 USB 是否连接。

## 实现与验证

`gimbal_imu_text.c` 统一 USB/USART10 文本列和单位；`gimbal_imu_uart.c` 在低优先级
通信任务中读一致的控制调试快照，使用 USART10 中断发送和固定缓冲。
发送未完成时跳过，避免改写正在发送的数据。USB 波形模式仍使用原 48 通道协议，
文本模式另加 `imu 0/1` 切换和可读应答；未更改 USART10 的 CubeMX 初始化、PID 或电机控制阶段。
当前云台入口不调用使用同一 USART10 的旧 `AUTOCMDInit/RefereeInit`；将来恢复
裁判系统前需要关闭或迁移此日志输出。

开关和发送间隔在 `gimbal_manual_config.h`：`GIMBAL_IMU_UART_ENABLED`，
`GIMBAL_IMU_UART_PERIOD_MS`，默认 1 和 50 ms。

代码验证：sentry、infantry 均从新建构建目录完整编译通过；主机测试通过控制器、
遥控、VOFA+ 协议/运行时及串口日志检查。日志检查覆盖单位、负号、异常值、容量、
发送期间缓冲保护、忙时跳过、表头重发/失败重试和时钟溢出；USB 检查文本上电、
可读命令应答、暂停、忙时跳过及恢复 JustFloat；运行时检查安装姿态
触发控制故障时仍提供传感器轴调试数据。构建存在旧模块的未使用变量/函数等警告，
新增日志模块未产生编译警告。

硬件验证待执行：DM-MC02，BMI088，Yaw CAN1 ID1 / Pitch CAN2 ID2 GM6020，
USART10 TX 接 USB-TTL RX、共地；观察 CSV 新鲜度、静止值、单轴动作符号、零输出，
同时确认 USB VOFA+ 48 通道及 `stop` 命令正常。代码构建/主机测试不能替代该实机验证。
USB 临时采集同样待实机验证：开发板 USB 枚举、文本列/新鲜度和 `imu 0/1` 切换。
开始遥控推进前先执行 [遥控输入验证](remote_bringup.md)。sentry 的 CAN1 扫描仅在 USB
文本流开启时发送完整 `# CAN1_SCAN` 报告，JustFloat 和暂停模式下不混入扫描文本。

# Pitch速度与遥控掉线试验（2026-10-10）

本页保留上一轮单轴速度试验记录。当前双轴操作以[双轴遥控与保持](dual_hold_bringup.md)为准，默认stage=2。
以下stage=1和参数是历史试验值。
Yaw保持已获用户认可的参数；USB默认文本，USART10和JustFloat列序保留。

## 上一轮硬件记录

DM-MC02/STM32H723、BMI088、UART5 DT7，CAN1 ID1 Yaw、CAN2 ID2 Pitch均反馈健康。
用户反馈无嗡鸣、后面卡住、速度和力度不足，且没有关闭遥控或操作接收器接线。
目标-45 deg/s时实际约-37～-38 deg/s，CAN输出约4800～5400，未达到10000上限。
在t=28199 ms、ECD1261时首先出现rc_online=0、state=4、fault=1、两轴输出0。
输入停留在旧值328，约5.3秒后rc_online恢复，但未经过OFF重新准备，故保持锁存停机。
之后t=35299 ms显示fault=9（RC故障1叠加限位故障8），不是单纯被负载堵转。
具体接收异常原因未由旧日志确定，不把电流原始值直接解释成A或N·m。

## 本轮变化

Pitch普通速度上限45→90 deg/s，加速度180→360 deg/s²，余量区朝内退出20→30 deg/s。
Kp保持20000，Ki12000→18000，积分上限5000，总输出上限10000。
硬端点384/1394、软范围484～1294、命令/反馈/输出符号保留。
增大速度目标和Ki用于更快建立纠偏，实际速度和带载能力仍需上板验证。

串口BSP记录接收启动失败、错误次数/错误码；RC读取时只在UART和DMA均已停止后
尝试重新启动接收，不中断正在收的帧，也不打断异步DMA终止过程。
短帧在读帧字段前拒绝。原完整帧校验、100 ms超时、坏帧立即离线规则均保留。
UART的重启只恢复接收，不清除云台故障，不自动续跑。
该修复覆盖了接收引擎停止/启动失败的情况，不代表已证明此次掉线根因就是该情况。

USB每250 ms追加一行`# RC`，CSV及48通道JustFloat不变：

| 字段 | 说明 |
| --- | --- |
| age_ms / ok | 最近有效帧年龄 / 有效帧累计次数 |
| bad / len / why | 坏帧累计次数 / 最近回调长度 / 最近坏帧原因 |
| why | 0无，1长度不是18，2拨杆非法，3鼠标按键非法，4通道越界 |
| uart_err / err | UART错误次数 / 最近HAL错误位图，以十六进制打印 |
| retry / start_fail | 停止后任务重启次数 / HAL启动接收失败次数 |

如果ok停止增长且age持续增大，是没有新的有效帧；bad增长则有输入但校验失败。
uart_err和start_fail增长说明UART或接收重启存在异常，需要结合接线和供电排查。
这些诊断不改变故障判定，也不能仅凭一个累计值确定当前故障。

## 用户操作

1. 烧录新版，不发送调参命令。左拨杆中档仅Pitch，右拨杆下档、摇杆回中；
   两台电机保持通信，等stage=1、state=1、fault=0、axis_mask=2。
2. 右拨杆上档保持，前推半行程0.3秒，再回中观察0.3秒，右拨杆回下。
   半杆普通区域目标约-38.8 deg/s；退出余量区目标最多-30 deg/s。
   满杆普通区域最高-90 deg/s，临近端点仍按距离减速；本轮先不用满杆跑完整行程。
3. 提供准备、使能、推杆、回中及OFF的完整日志，保留`# RC`、`# CTRL`、`# MOTOR`。
   若再停住，先右下档并回中，等待rc_online=1、state=1、fault=0后才重新使能。
   仍有故障就保存日志，不持续推杆试图清故障。下档无驱动力，安排支撑接住机构。

## 软件验证

七组主机测试通过：控制器、真实RC解码、真实USART BSP、VOFA协议、USB真实运行层及
电机适配器、USART10打印、CAN扫描。验证正常区90/恢复区30的速度上限与10000输出限制、
接收停止重启/失败再试、活跃及终止中的DMA不被重启、错误计数、短帧和帧年龄诊断、
失联停机及恢复后仍须OFF，以及原限位/STOP互锁。infantry/sentry在pitch-rc-*-20261010
